# Guga Abuser Blocker · 0.2.1 プレビュー

[简体中文](README.zh-CN.md) · [English](README.en.md)

Guga コミュニティの管理リストに含まれるアカウントの表示を減らす Chrome / Edge 拡張機能です。対象範囲はリストに依存し、未登録のアカウントが表示される場合があります。日本語・英語・中国語に対応しています。管理者の公開リストを購読し、自分の例外を設定して、ログイン中の X アカウントで自動ブロックを有効にできます。ローカル取り込みと非公開バックアップにも対応し、初期状態では自動ブロックはオフです。

**購読は読み取り専用です。拡張機能から公開リポジトリへのアップロード・配信・候補の投稿はできず、GitHub PAT も受け付けません。** 自分の取り込み・確認・編集はこのブラウザー内に保存されます。公開リストは管理者が別の手順で配信します。

## リポジトリと購読

[リリース](https://github.com/ZOC698/guga-abuser-blocker/releases) · [公開リスト](lists/guga-blocklist.json) · [管理者向け手順](CONTRIBUTING.md)

## インストールと購読

1. パッケージを展開して保管します。`chrome://extensions` または `edge://extensions` でデベロッパーモードを有効にし、`manifest.json` が直接入った **extension** フォルダーを読み込みます。
2. このブラウザープロファイルで X にログインします。ツールバーのアイコンから、5 つの管理パネルをポップアップ内で開けます。
3. 「リスト購読」に上の公開 URL を追加し、`raw.githubusercontent.com` の読み取りを許可します。購読者にターミナル、Codex、GitHub アカウント、PAT、X 開発者 API キーは不要です。
4. 「X セッションを接続」を押します。バックグラウンドでログインセッションを確認し、数値アカウント ID に接続します。**0.1.x から更新した後は、ブロックを有効にする前に再接続が必要です。** 開発者 OAuth 認可ではありません。
5. 自動 X ブロックを有効にします。確認済みで数値 ID がある項目をバックグラウンドで処理します。ブラウザーは起動しておいてください。専用の X プロフィールタブは不要です。リクエスト間隔は 30〜300 秒です。

X のログイン状態が必要です。アカウント・セッション変更や認証失敗時には再接続してください。制限、リクエスト予算、通信エラーにより待機期限が設定される場合があります。ポップアップを閉じたりバックグラウンドを再起動したりしても待機は解除されません。

Chromium 120 以降が必要な開発者読み込みプレビューです。実際の X での Chrome / Edge の環境別検証は未完了です。購読は手動、またはブラウザーが動作可能な間は約 6 時間ごとに更新します。スリープ・電源オフ・調整によって遅れる場合があります。更新後は拡張機能を再読み込みし、投稿の非表示を更新するため X タブも再読み込みしてください。

## 非公開のアカウント一覧

TXT・CSV・JSON のプレビューと取り込み、またはユーザー名の貼り付けができます。新規項目はファイル内の承認状態にかかわらず未確認になります。内容を確認してから自分の非表示・ブロックに使用してください。確認済みにしても公開されません。

ローカル項目の「編集」で数値ユーザー ID を追加・修正できます。1〜25 桁の数字を文字列として保存します。既知の ID の修正後は未確認に戻り、欠けている ID の追加では確認状態を維持します。既知の ID は空にできません。現在のユーザー名も必要です。取り込み結果には新規・更新・重複の件数を表示します。統合規則は[データ形式](DATA_FORMAT.md)を参照してください。

既存のブロック一覧を収集するには [X Blocked accounts](https://x.com/settings/blocked/all) を開き、管理画面から収集を開始して結果を取り込みます。X が表示した項目だけが対象です。収集の待機状態は全件取得の保証になりません。

非公開 JSON / CSV はローカル項目のみのバックアップで、設定・購読・履歴の全体ではありません。再取り込みした新規項目には確認が必要です。個人のバックアップを公開リポジトリや配布パッケージに含めないでください。

## ブロック方法と制限

0.2.1 はブラウザーの X ログインセッションで、X のウェブ内部 API にバックグラウンドリクエストを送信します。ブロック関係を API で確認してから成功を記録し、プロフィールのメニューはクリックしません。内部エンドポイントは公開された開発者 OAuth API とは異なり、X の更新で変更される可能性があります。

ブロックには既知の数値対象 ID が必要です。ユーザー名だけの確認済み項目は「数値 ID 待ち」となり、ブロック要求を送りません。ローカル項目は編集で補い、購読項目は管理者の更新を待ってください。待機列はユーザー名から自動で ID を検索してブロックしません。実行前後に対象と接続アカウントの数値 ID を確認します。投稿の非表示は引き続きユーザー名で照合します。

フォームとパネルの下書きは現在のブラウザーセッションに保存されます。接続結果、待機列、待機期限は別に保存され、ポップアップを閉じても失われません。

例外は今後の非表示・ブロックに優先します。購読や項目の削除、例外の追加で既存の X ブロックは解除されません。解除は X で行ってください。一時停止はできますが、送信済み操作は撤回できません。不確定な結果は履歴と X を確認してから再試行してください。

実際の X でのブラウザー・言語・アカウント状態をまたぐ一連の検証は未完了です。模擬ページのテストが証明するのは、模擬した条件だけです。[検証記録](VERIFICATION.md)を参照してください。

## 公開リストの管理

書き込み権限を持つ管理者だけが [CONTRIBUTING.md](CONTRIBUTING.md) の独立した CLI 手順で配信します。購読拡張には公開用書き出し・アップロード・リポジトリ作成・候補投稿の入口がありません。購読者によるリスト PR を配信手順にせず、GitHub の権限で共有ファイルへの書き込みを管理します。

Twitter 鳥盾の共有リスト方式を参考にした独立実装です。そのソース・アイコン・リストを同梱せず、完全な形式互換性や同等の信頼性も主張しません。
